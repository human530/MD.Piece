# 腎病病因階層模型（感染／免疫／代謝）——真實公開資料版

**核心概念（使用者定義）**：用「已知」找「未知」——不預先指定哪些血液標記，把**所有可得的常規檢驗全部**餵進模型，
先分出三大病因（感染性／免疫性／代謝性），再往下拆細項（如免疫性 → 是哪一種免疫問題），
並回報「是哪些 biomarker 組合把個案推向哪個病因」。

## 三條鐵則（程式層強制，違反即 raise）

1. **只用真實資料**：不自製個案、不合成、不虛擬。每個輸入檔必須在 `results/provenance.json`
   有登錄（來源 URL＋SHA256＋位元組數＋下載時間），`src/provenance.py` 的 `require_real()` 未登錄即拒跑。
2. **標籤來源檢驗不得作為特徵**（通道消耗規則）：用糖尿病診斷/HbA1c 定義「代謝性」，HbA1c 就進封存集；
   用 B/C 肝血清定義「感染性」，肝炎血清就進封存集；用 ANA/dsDNA 定義「免疫性」，自體抗體就進封存集。
   否則 AUC 是循環論證，不是發現。
3. **AUC 是結果不是承諾**：目標 ≥0.90 只影響「設計」（階層式 one-vs-rest、全標記特徵空間、
   梯度提升＋校準、巢狀交叉驗證），**不得**在測試資料上調整任何東西去湊數字；跑出多少報多少。

## 架構

```
Level 0  資料閘門        真實出處帳本＋缺值=NaN＋成人＋腎損傷定義（eGFR<60 或 ACR≥30）
Level 1  三大病因        感染性 / 免疫性 / 代謝性（多類，含拒答「無法判定」）
Level 2  類內細項        依標籤可得性：免疫性→ANA 型態/特異抗體亞群；感染性→HBV vs HCV；代謝性→糖尿病 vs 其他
Level 3  biomarker 歸因  每類的驅動標記（係數/SHAP + 單變量效應量 + 文獻對照：已知 vs 候選未知）
────────────────────────
佐證層   腎臟超音波      us_validation/ 介面——等真實影像資料到位才會運作（見下）
```

- 模型：可解釋基線（L2 logistic）＋ 主模型（梯度提升 HistGradientBoosting，原生吃 NaN）＋ 機率校準；
  巢狀 CV（外層評估、內層調參），測試折永不參與任何選擇。
- 「導致」的誠實界線：橫斷面檢驗資料只能建立**關聯**與**判別**，不能證明因果；報告一律寫
  「與病因分類相關的標記組合」，因果語句需要縱貫/介入資料。

## 資料現實（2026-08-30 盤點中，scout 工作流查證）

- **NHANES**（美國 CDC，真實人類、公開下載）：常規檢驗全景 + 糖尿病 + B/C 肝血清；
  **只有 2003–2004 週期**測過 ANA/自體抗體（surplus sera 研究）→ 免疫性標籤僅該週期可得。
  病因標籤是「共病代理」（questionnaire 診斷＋血清學），**不是切片證實**——這個限制會印在每份輸出上。
- **腎臟超音波**：公開世界目前**沒有**上萬張且帶病因標籤的腎超音波資料集（最大的公開集僅數百張，scout 確認中）。
  「萬張超音波佐證」需要醫院端資料——`us_validation/` 已定義好交換格式與一致性分析，
  影像與標籤一到位即可跑；在那之前它會拒絕執行，不會生出任何假結果。
- Level 2 的病理級細項（狼瘡 vs IgA vs 膜性…）公開資料無法標→以 NHANES 自體抗體亞群近似（免疫內部），
  其餘細項留介面等臨床資料。

## 跑法

```bash
python fetch_data.py            # 下載 manifest 內的真實檔案 → data/raw/ ＋ provenance.json
python pipeline.py              # 閘門 → 標籤 → 封存集 → 特徵 → 巢狀 CV → Level 1/2/3 → 報告
python figures.py               # 圖
python ui/export_viz.py         # 離線視覺化
python nephritis_proxy.py       # ANA 實測子世代：免疫相關腎損傷代理模型，5×5 重複巢狀評估＋完整模型封裝
```

## 「腎炎」模型的可用邊界

NHANES 沒有腎切片或臨床腎炎診斷，因此 `nephritis_proxy.py` 不把 ANA 陽性冒充為腎炎。
它只在 **ANA 確實有檢測** 的腎損傷成人中，預測 ANA／特異自體抗體陽性的「免疫相關腎損傷代理」。
輸出的 joblib 是可重現的研究模型，不可直接用於臨床診斷；完整限制、重複驗證與每折結果均寫入
`results/nephritis_proxy_repeated_eval.json`。

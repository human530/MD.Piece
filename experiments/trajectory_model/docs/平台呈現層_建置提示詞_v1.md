# 一、角色與語氣

你撰寫的所有介面文案，設定為一位資深臨床工作者對病人說明檢驗結果時的語氣。
特徵是：句子短、每句只講一件事、用具體的日常現象作說明、
不加修飾性形容詞、不預測對方的情緒、不替對方下決心。

必須做到「沒有受過訓練的人也讀得懂」，但不得使用兒童化語氣。
判準：可以說「球被推一下之後，要花比較久才回到原位」，
不可以說「哇，這顆小球累累的，要休息一下才回得了家喔」。

## 禁用語彙（出現即為不合格）

- 驚嘆號
- 「讓我們一起」「接下來我們要」「首先」「總而言之」
- 「很重要的是」「值得注意的是」「需要特別強調」
- 「太棒了」「別擔心」「放心」「請安心」
- 「智慧」「賦能」「一站式」「全方位」「精準守護」等行銷詞
- 任何以問句開場帶動節奏的寫法（例如「你知道嗎？」）
- 表情符號

## 語氣對照範例

| 不合格 | 合格 |
|---|---|
| 讓我們一起來看看您的健康趨勢吧！ | 以下是模型依你輸入的數值所產生的結果。 |
| 這個數值非常重要，值得您特別注意喔 | 這個數值決定模型把你歸到哪一類。 |
| 別擔心，這不代表您一定會生病 | 這是模型的輸出，不是你的診斷。 |
| 我們的智慧引擎為您精準分析 | 計算方式與每一個係數的出處列在下方。 |

# 二、產品定位（此段決定整個介面的骨架，不可調整）

這個介面呈現的是一個以合成資料建立的研究模型，不是個人風險評估工具。

使用者輸入數值之後，介面要說明的是「你的輸入落在這個模型的什麼位置」，
而不是「你未來會怎樣」。這兩件事必須在文案上嚴格區分。

介面頂端須有一條常駐說明列，不可關閉、不可摺疊，內容固定為：

  本工具以合成資料建立之研究模型運算，非個人風險評估，不做診斷，不取代醫師。

# 三、畫面結構

四個區塊，由上而下單欄排列，桌機寬度 960px 置中，手機單欄堆疊。

## 區塊一：輸入

分兩組。

第一組為數值輸入，欄位由 `params/ui_fields.json` 驅動，
每個欄位需有：欄位名、單位、合理範圍、預設值、來源標籤。
前端不得硬寫任何欄位。

第二組為疾病因子勾選，同樣由參數檔驅動。
**參數檔中沒有出處的因子，不得出現在介面上。**
每個勾選項旁附一個資訊圖示，點開顯示該因子的係數與出處。

另設三個進階滑桿，預設收合：
量測誤差（對應醫院檢驗到自填的精度差異）、
量測間隔（每日至每半年）、
系統鬆弛時間 τ。

## 區塊二：運算

一個「計算」按鈕。點擊後即時運算並捲動至結果區。
運算過程須顯示逐步狀態（讀取參數、標準化輸入、分類、模擬、計算指標），
每步顯示實際執行的動作名稱，不得使用進度條配假文字。

## 區塊三：結果

結果分三層，預設全部展開，使用者可逐層收合。

第一層：模型輸出。一句話加一個數字。
  例：模型將此組輸入歸為翻轉型，機率 0.62。

第二層：這個數字怎麼來的。
  列出實際參與運算的輸入項、套用的公式、每一項的權重與貢獻量。
  以表格呈現，每列一個輸入項，欄位為：輸入值、標準化值、權重、貢獻量。
  表格下方以一行說明加總方式。

第三層：這些權重從哪裡來。
  每一個權重列出來源標籤與出處。來源標籤只有三種：

  | 標籤 | 意義 |
  |---|---|
  | 抄錄自文獻 | 直接取自已發表論文，附作者、年份、PMID |
  | 由文獻推算 | 自論文的文字或圖推算，附推算方式 |
  | 本研究設定 | 無文獻可依，由本研究設定，附設定理由與敏感度範圍 |

  三種標籤的數量須即時統計並顯示，例如「本次運算使用 14 個係數：
  抄錄 8、推算 3、設定 3」。這是本介面最重要的一項功能，不得省略或摺疊隱藏。

## 區塊四：軌跡與說明

上方一張圖，顯示模型依此組輸入生成的代表性序列，
標出漂移起始日、臨界日、門檻跨越日、事件日、首次警報日五個時點。

下方為說明文字，三段，每段不超過三句：

  第一段說明這張圖在畫什麼。
  第二段說明為什麼要看恢復速度而不是數值高低。
  第三段說明這個結果不代表什麼。

第二段須使用具體的日常現象作說明，且全段句長不超過二十字，
不使用比喻性形容詞、不使用擬人化、不使用語助詞。

# 四、運算規格

前端不得自行實作模型。二擇一：

（甲）優先方案：載入 Python 端預先計算的查表與係數（JSON），前端只做查表與內插。
（乙）若必須即時模擬：以 mulberry32 種子化亂數移植，
     並以 node 對照 Python 輸出驗證，誤差容許值寫定於程式註解，
     驗證腳本一併交付。

無論何種方案，同一組輸入必須永遠得到同一組輸出。

# 五、資料與隱私

- 全部運算在瀏覽器端完成，不發送任何請求
- 不使用 cookie、不寫入任何儲存
- 使用者輸入不離開該次工作階段
- 此三項須明列於頁尾，並可由使用者以開發者工具自行驗證

# 六、技術規格

- 單一 HTML 檔，自含，無外部相依，可離線開啟
- 不使用任何框架；原生 JS
- 版面以中性色為主，僅在標示來源標籤時使用有限的色彩區分，
  且色彩不得為唯一的區分方式（同時附文字標籤，供色覺障礙者使用）
- 字型使用系統字型堆疊，中文優先
- 對比度符合 WCAG AA
- 全部控制項可用鍵盤操作

# 七、禁止事項

1. 禁止顯示任何未附出處的數字。
2. 禁止使用「你的風險」「你的預測」「你會」這類指涉使用者本人的句式；
   一律寫成「模型的輸出」「此組輸入」。
3. 禁止提供任何醫療建議、用藥建議或就醫時機建議。
4. 禁止把模型輸出呈現為紅黃綠燈號或分數等第，那會被讀成診斷。
5. 禁止在前端硬寫任何係數、欄位或疾病因子。
6. 禁止收集使用者資料，包含匿名統計。
7. 禁止使用第一節的禁用語彙。

# 八、驗收清單

交付前逐項自檢並回報結果：

1. 常駐說明列是否無法關閉
2. 隨機挑五個顯示中的數字，是否都能點到出處
3. 三種來源標籤的計數是否正確且顯示於顯眼位置
4. 同一組輸入連按十次計算，輸出是否完全一致
5. 斷網後開啟是否仍完全可用
6. 全部文案是否通過禁用語彙檢查（請寫一個檢查腳本，附交）
7. 僅用鍵盤是否可完成一次完整操作
8. 區塊四第二段是否每句都在二十字以內

請先回覆你對這份規格的理解，並列出你認為最容易做錯的三個地方，
確認後再開始。

## 交付後的檢查方式

程式助理交回之後，以下三項由你親自確認，不要只看它的自我回報。

| 項目 | 怎麼查 |
|---|---|
| 是否有無出處的數字 | 隨機點五個數字，看有沒有出處彈窗 |
| 是否偷偷變成算命工具 | 搜尋文案中是否出現「你的」二字 |
| 是否真的離線可用 | 關掉網路重新開啟 |

第二項最容易失守。介面做得越好用，就越容易寫成第二人稱，
而一旦寫成第二人稱，它在讀者眼中就從研究工具變成診斷工具。

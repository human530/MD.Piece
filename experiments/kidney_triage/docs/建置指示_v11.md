# 任務：建置腎損傷分流模型（Stage 0–5）

你是一位同時具備腎臟科臨床知識與預測模型方法學訓練的研究工程師。請依以下規格，用 Python 建置一個**腎損傷分流模型**，並產出完整的分析報告。

## 〇、這個模型在做什麼（先讀懂再動手）

不是「從抽血推測病名」。是**在醫師開出任何專項檢驗之前，用已經有的常規檢驗，把範圍縮小，並指出下一步該開哪一張單**。

```
Stage 0  資料品質與密度閘門
Stage 1  急性度        腎功能下降得快不快
Stage 2  部位          腎絲球／腎小管間質／血管
Stage 3  表現型        腎病症候群／腎炎症候群／孤立血尿／慢性
Stage 4  分流格        Stage 1–3 之組合，六格
Stage 5  建議檢驗      該格該加驗哪一項，或不必加驗
────────────  模型邊界，到此為止  ────────────
（不屬於模型）確認：培養／抗體／基因／腎臟切片，由醫師執行
```

**Stage 6 不要實作。** 模型不預測最終病名、不決定切片、不建議治療。

## 一、硬性約束（違反其一即為建置失敗）

這七條是方法學前提，不是風格偏好。每一條都要在程式裡有**執行期斷言**，不通過就 raise。

1. **通道消耗規則**：凡被用於定義參考標準（標籤）的檢驗，一律列入「封存集」，不得作為任何階段的特徵。封存集預設為：抗核抗體、抗雙股 DNA、抗 Sm、抗 C1q、抗 PLA2R、抗 THSD7A、ANCA、抗 GBM、免疫固定電泳、血清游離輕鏈、血清 IgG4。
2. **禁止逐人標準化**。所有標準化一律以**全世代**的中位數與標準差進行。逐人標準化會破壞跨通道誤差獨立性，這是本方法的數學前提。
3. **Stage 1–3 只能使用「零新增檢驗集」**（見第二節）。補體、自體抗體、游離輕鏈等須特別開立的項目，不得進入這三個階段。
4. **洩漏基準 M0 必須先建、先定版**。每一階段各自建立一個只用「哪些檢驗被開立」之指示變數的模型。**在 M0 定版並存檔之前，不得計算或印出任何主模型的效能數字。** 程式流程上要強制這個順序。
5. **未開立 ≠ 陰性**。缺值一律以 NaN 表示並以缺值處理，不得填 0。
6. **拒答是必要功能**。任一階段最高類別機率低於門檻者，輸出「無法判定」並停止往下，不得強行分類。
7. **無文獻依據的參數一律留 null**，程式啟動時列印警告，不得自行填值。

## 二、資料契約

### 輸入一：縱向檢驗（long 格式，一列一次同日成套）

| 欄位 | 說明 |
|---|---|
| `patient_id` | 去識別化病人序號 |
| `panel_no` | 該病人的第幾次成套 |
| `day_from_index` | 距索引日之天數 |
| 各通道欄位 | 見下方通道清單；未開立者為 NaN |

### 輸入二：病人層級

| 欄位 | 說明 |
|---|---|
| `patient_id` | 對應 |
| `n_panels` | 追蹤期內同日成套次數 |
| `ord_*` | 各專項檢驗是否被開立（0/1）——**M0 的唯一特徵來源** |
| `label_*` | 參考標準（見第四節） |

### 通道清單

**零新增檢驗集 L1（Stage 1–3 只能用這些）**

```
Cr        血清肌酸酐
BUN       血中尿素氮
UPCR      尿蛋白／肌酸酐比
uRBC      尿沉渣紅血球計數
uRBC_dys  尿沉渣變形紅血球（有／無或計數）      ← 若資料無此欄位，見第七節備案
uRBC_acan 尿沉渣棘形紅血球
uRBC_cast 紅血球圓柱
uWBC      尿沉渣白血球
NLR       嗜中性球／淋巴球比
CRP       C 反應蛋白
SBP       收縮壓
alb       血清白蛋白
eos       血中嗜酸性球
PLT       血小板
```

**需開立但常規可得 L2（僅用於 Stage 5 之後與敏感度分析）**

```
C3, C4, pctUAE（尿白蛋白占總尿蛋白）, LDH, HbA1c, sIgA
```

**封存集（絕不得作為特徵）**

```
antidsDNA, ANA, antiSm, antiC1q, PLA2R, THSD7A, ANCA, antiGBM, IFE, sFLCr, IgG4
```

## 三、特徵建構

對每個病人、每條通道，計算三種讀法：

| 特徵 | 定義 | 命名 |
|---|---|---|
| 水準 | 對數值中位數之全世代標準化 z 分數 | `L_<通道>` |
| 變化率 | 對數值對天數之線性斜率，年化並以全世代標準差標準化；需 ≥3 次測量且時間跨度 >0 | `S_<通道>` |
| 相對關係 | 兩通道水準之差（＝對數比值） | `R_<通道A>_<通道B>` |

**事前指定的優先比值**（一定要建，且在報告中單獨列出其表現）：

```
R_Cr_UPCR      肌酸酐／UPCR        → 腎小管間質 vs 腎絲球
R_UPCR_alb     UPCR／白蛋白        → 腎病症候群之完整程度
R_UPCR_uRBC    UPCR／尿紅血球      → 足細胞型 vs 增生型
R_BUN_Cr       尿素氮／肌酸酐      → 腎小管間質
R_CRP_alb      CRP／白蛋白         → 發炎相對於營養狀態
```

## 四、參考標準（標籤）

由病理與專家共識定義，**依 Mayo Clinic／腎臟病理學會共識之主要診斷結構**（疾病實體／致病型 → 損傷型態 → 分級 → 附加特徵）。程式只讀標籤，不重建判定邏輯。

| 標籤 | 類別 |
|---|---|
| `y_acute` | 0／1（腎功能是否快速惡化） |
| `y_site` | 腎絲球／腎小管間質／血管 |
| `y_pheno` | 腎病症候群／腎炎症候群／孤立血尿／慢性 |
| `y_box` | 由上三者依第五節規則導出 |

## 五、Stage 4 分流格規則

```python
def box(acute, site, pheno):
    if site == "血管" or (acute and site == "腎絲球"):
        return "R"          # 急進型（RPGN／TMA 未分）
    if site == "腎小管間質":
        return "A" if acute else "A2"   # 急性／慢性腎小管間質
    if pheno == "腎病症候群": return "C"
    if pheno == "腎炎症候群": return "D"
    if pheno == "孤立血尿":   return "F"
    return "E"              # 慢性／硬化
```

> **R 格為何合併**：ANCA 相關血管炎與抗腎絲球基底膜病在常規檢驗上與血栓性微血管病幾乎相同（三者皆為微血管病變）。強行分開會使該格正確率崩到 0.29；合併後回到 0.73。臨床上急進型本來就是一次開一整套。**不要試圖把 R 格再細分。**

## 六、逐階段模型階梯

每一階段（1、2、3）各自建立四層，**順序不得調換**：

| 層 | 特徵 | 何時建 |
|---|---|---|
| `M0ᵢ` | 只用 `ord_*` 指示變數 | **第一，且須存檔定版** |
| `M1ᵢ` | 索引時點之 `L_*`（L1 集） | 第二 |
| `M2ᵢ` | `L_*` ＋ `S_*` ＋ `R_*`（L1 集） | 第三 |
| `M3ᵢ` | M2ᵢ 排除封存集與 `ord_*` | 第四 |

模型：`StandardScaler` → `LogisticRegression(penalty='l2', class_weight='balanced')`，5 折分層交叉驗證。**不要用不可解釋的模型**——本研究必須能說明「這項推測由哪些指標支持」。

### 判定規則（事前鎖定，不得事後調整）

| 比較 | 未通過的處置 |
|---|---|
| M2ᵢ vs M0ᵢ | **該階段自管線移除**，照實報告「該軸不具生理訊號」 |
| M2ᵢ vs M1ᵢ | 報告為無增額價值（不移除） |
| M3ᵢ vs 隨機 | 報告為無獨立增益 |

**逐階段停止，不是整案停止。** 某軸失效只砍該軸。

## 七、若尿沉渣形態欄位不可得

先檢查 `uRBC_dys` / `uRBC_acan` / `uRBC_cast` 的可得比例。若低於 30%：

- Stage 3 改用 `L_uRBC` 與 `R_UPCR_uRBC` 作為代理
- 在報告中以顯著方式標明「腎絲球來源判定使用代理特徵，特異度預期明顯下降」
- 額外輸出「形態欄位可得 vs 不可得」兩子群的表現比較

## 八、拒答

- 每階段輸出 `predict_proba`，取最大值為信心。
- 門檻**在訓練資料上**依「作答率—正確率」曲線選定並鎖定，不得在測試資料上調整。預設起點 0.6。
- 報告必須同時給出：**拒答率**與**作答者的正確率**。只報作答者正確率屬選擇性報告，視為錯誤。

## 九、報告指標

**主要指標是平衡正確率，不是整體正確率。** 類別高度不平衡時整體正確率會嚴重誤導。

每一階段與分流格都要報：

1. 整體正確率、**平衡正確率**、逐類召回率
2. **依本族群實際盛行率換算的陽性與陰性預測值**（不可只報敏感度／特異度／AUC）
3. 各層 M0／M1／M2／M3 與判定結果
4. **M0 逐族群報告**（不可只報整體——某些族群的洩漏會遠高於平均）
5. 95% 信賴區間（bootstrap，≥1000 次）

## 十、Stage 5 建議之評估

模型的最後輸出會被醫師照著開單，所以建議本身要被評估：

| 指標 | 定義 |
|---|---|
| 檢驗節省率 | 依建議開單 vs 全面開單，減少的檢驗項目比例 |
| **關鍵遺漏率** | 應開立而未建議之比例。**R 格的強制五項為零容忍** |
| 建議命中率 | 建議之檢驗中，實際對最終判定有貢獻者之比例 |

### R 格硬性規則（不得由模型機率覆蓋）

落入 R 格者，建議一律為下列五項**同時開立**：

```
血液培養、ANCA、抗腎絲球基底膜抗體、
全血球計數（含血小板）＋LDH＋破碎紅血球、免疫固定電泳
```

理由：ANCA 相關血管炎與感染性心內膜炎相關腎炎在常規檢驗上難以分辨，而誤判之後果為將免疫抑制治療用於活動性感染。這一格靠檢驗不靠模型。

### 其餘各格之建議（依實測增益）

| 格 | 建議 |
|---|---|
| A 急性腎小管間質 | 病史與用藥回顧為主（檢驗增益極小）；尿沉渣白血球、嗜酸性球 |
| C 腎病症候群型 | 抗 PLA2R、B 肝血清學、年齡與癌症篩檢（常規在此格內部低於亂猜） |
| D 炎症性腎絲球 | 補體 C3／C4 ＋ 自體抗體（此格加驗增益最大） |
| E 慢性／硬化 | 常規已足夠，**不建議加驗** |
| F 孤立血尿 | 家族史、聽力與眼科；COL4A 基因 |

## 十一、必要的自我檢查（寫成 assert）

```
assert 封存集所有欄位都不在任何特徵矩陣中
assert 沒有任何逐人標準化（標準化參數來自全世代）
assert M0 已存檔且時間戳早於任何主模型效能計算
assert 未開立的通道為 NaN，不是 0
assert Stage 1–3 的特徵全部來自 L1 集
assert 每個階段都有回報拒答率
assert 主要指標包含平衡正確率
assert 隨機種子已固定，重跑結果一致
```

## 十二、交付物

1. `pipeline.py`——完整可重現的管線（含所有 assert）
2. `report.md`——依第九、十節的完整報告
3. `m0_baseline.json`——M0 定版存檔，含時間戳
4. `thresholds.json`——各階段拒答門檻與其選定依據
5. `feature_importance.csv`——各階段係數，供「這項推測由哪些指標支持」使用
6. `limitations.md`——實際遇到的資料限制與其後果

## 十三、絕對不要做的事

- 不要新增病因類別來提升覆蓋率——加類別會稀釋訊號並放大洩漏，要加的是**通道**。
- 不要把研究用生物標記（Gd-IgA1、尿 sCD163、尿 CXCL9、miRNA）放進模型——回溯資料庫拿不到。
- 不要嘗試細分 R 格，也不要在 A 格用檢驗去分四個病（答案在用藥史）。
- 不要因為結果不好看就調整判定規則或拒答門檻。
- 不要只報 AUC。
- 不要實作 Stage 6。

## 十四、如果結果是陰性

若某一軸的 M2ᵢ 未顯著超越 M0ᵢ，**照實報告並把該軸移除**。這是有價值的結論——它說明在扣除檢驗開立型態之後，常規檢驗於該軸不含額外資訊。不要調參去救它。
